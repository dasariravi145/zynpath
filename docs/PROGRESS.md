## 3. Detailed Deliverables for Prompt 06

### 3.1 Pure Kotlin Domain Models (`com.zynpath.game.core.puzzle.model`)
- `GridPosition`: Immutable 0-indexed coordinate `(row, column)`. Manhattan distance, orthogonal neighbor calculation, and canonical row-major ordering. Backward-compatibility alias `GridCoordinate`.
- `GridDimensions`: Rectangular and square board boundaries with overflow safety limit (`MAX_DIMENSION = 50`) and row-major deterministic cell enumeration.
- `Direction`: Strictly orthogonal directions (`UP`, `DOWN`, `LEFT`, `RIGHT`) with row/column deltas, opposite direction mapping, and orientation queries.
- `NumberedCheckpoint`: Checkpoints #1..N with position and `#1` start flag. Contiguity and uniqueness enforced.
- `BlockedEdge`: Direction-independent wall representation between adjacent cells (`BlockedEdge(a,b) == BlockedEdge(b,a)`) with canonical endpoint ordering (`first <= second`) and set deduplication. Backward-compatibility alias `WallEdge`.
- `PuzzleCell`: Decoupled domain cell holding position, required status, and optional checkpoint.
- `GridGraph`: Planar graph representation for fast constant-time boundary checks, wall collisions, and unblocked neighbor queries.
- `PuzzleDefinition`: Immutable puzzle level specification with precomputed lazy checkpoint map and grid graph.
- `PathSegment`: Directed orthogonal connection between consecutive positions with orientation indicators.
- `PuzzlePath`: Immutable ordered path representation preserving sequential traversal history with $O(1)$ membership lookup, cycle detection, and non-destructive operations (`plus`, `dropLast`, `retractTo`).

### 3.2 Structural Puzzle Definition Validation (`PuzzleDefinitionValidator`)
- Granular error descriptors (`DefinitionErrorCode`) rejecting malformed definitions: blank ID, invalid version, non-positive dimensions, missing/duplicate/non-contiguous checkpoints, out-of-bounds walls or cells, and non-adjacent walls.

### 3.3 Foundational Path Validation & Dual Win Condition (`FoundationalPathValidator`)
- Enforces origin at #1, orthogonal movement, no wall crossings, simple path (no cycles), and ascending checkpoint order.
- Dual win condition enforcement: reaching final checkpoint with uncovered cells is strictly NOT victory (`Incomplete(INCOMPLETE_COVERAGE_AT_FINAL_CHECKPOINT)`). Covering all cells in wrong checkpoint order is strictly NOT victory (`Violation(WRONG_CHECKPOINT_ORDER)`).

- **`GameStatus`**: `NOT_STARTED`, `IN_PROGRESS`, `COMPLETED`, `PAUSED`.

- **`MoveRejectionReason`**: Granular rejection codes (`START_MUST_BE_CHECKPOINT_ONE`, `OUT_OF_BOUNDS`, `EXCLUDED_CELL`, `NON_ADJACENT`, `BLOCKED_BY_WALL`, `CELL_ALREADY_VISITED`, `WRONG_CHECKPOINT_ORDER`, `PREMATURE_FINAL_CHECKPOINT`, `GAME_ALREADY_COMPLETED`, `GAME_PAUSED`, `INVALID_ACTION`).
- **`PuzzleEngineResult`**: `Accepted` (state transition with optional `ValidatedCompletionResult`) vs `Rejected` (preserves valid state, provides reason and message).
- **`PuzzleGameState`**: Immutable snapshot with coverage ratio, endpoint tracking, move counter, and presentation mapping `toBoardState(): PuzzleBoardState`.
- **`CompletionValidator`**: Dedicated independent 8-point validator ensuring victory is never awarded based on UI flags, counters, or path lengths alone.
- **`PuzzleEngine`**:
  - Validates and applies actions deterministically.
  - Starting path strictly gated at checkpoint #1.
  - Strictly orthogonal forward moves; rejects diagonals and multi-cell jumps.
  - Wall collision enforcement blocking moves across `BlockedEdge`.
  - Self-intersection / cycle rejection preventing revisited cells.
  - Strictly sequential checkpoint progression ($1 \to 2 \dots \to N$).
  - **Premature Final Checkpoint Rejection**: Entering final checkpoint with $< 100\%$ required cell coverage is rejected with `PREMATURE_FINAL_CHECKPOINT`.
  - **Drag-Backtracking**: Moving into the immediately preceding cell automatically triggers 1-step undo.
  - Multi-cell backtracking restores earlier required checkpoint numbers and coverage counts.
  - Start-cell backtracking preserves single-cell path at checkpoint #1; reset restores `NOT_STARTED`.
  - Invariant assertion (`assertInvariants`) verifying all 9 domain invariants.

## 5. Detailed Deliverables for Prompt 08

### 5.1 Puzzle Solver Domain Architecture (`com.zynpath.game.core.puzzle.solver`)
- **`PuzzleSolver`**:
  - Deterministic depth-first search with backtracking for exact Hamiltonian paths.
  - Warnsdorff's minimum-onward-degree and checkpoint proximity candidate ordering with deterministic tie-breaking.
  - Supports first-solution discovery (`maxSolutions = 1`), uniqueness proofs (`maxSolutions = 2`), and bounded multi-solution discovery.
  - Asynchronous off-main-thread execution via `solveAsync` on `Dispatchers.Default` with cooperative cancellation.
- **`SolverConfiguration`**: Immutable configuration controlling node limits, monotonic elapsed time budgets, sound pruning flags, and cancellation callbacks.
- **`SolverResult`**:
  - Authoritative outcome representation: `status`, `solutions`, `isExhaustive`, `isSolved`, `isUnique`, `uniqueness`, and `statistics`.
  - Non-negotiable distinction: finding one solution proves solvability (`isSolved == true`), but does not prove uniqueness unless exhaustive (`isUnique == isExhaustive && solutionCount == 1`).
  - Search limits do not prove unsolvability (`isUnsolvable == isExhaustive && solutionCount == 0`).
- **`SolverStatus`**: `SOLVED`, `UNSOLVABLE`, `MULTIPLE_SOLUTIONS`, `SEARCH_LIMIT_REACHED`, `CANCELLED`, `INVALID_PUZZLE`.
- **`UniquenessStatus`**: `UNIQUE`, `NON_UNIQUE`, `UNSOLVABLE`, `UNKNOWN`.
- **`SolverStatistics`**: Tracks explored nodes, backtracks, pruned branches, elapsed ms, and nodes per millisecond.
- **`SolverSearchState`**: Reversible search state with flat boolean bitmask visited tracking and $O(1)$ generation tokens for BFS buffers.
- **`SolverPruningRules`**: 5 conservative mathematical pruning rules:
  1. Premature final checkpoint entry check.
  2. Ascending checkpoint sequence check.
  3. Unvisited cell connectivity flood-fill check (treating final checkpoint as a barrier).
  4. Intermediate cell degree consistency check ($\ge 2$ for intermediate, $\ge 1$ for final).
  5. Checkpoint reachability check (cannot traverse higher checkpoints before current checkpoint).
- **`SolutionValidator`**: Authoritative validation gate ensuring every candidate passes `CompletionValidator` and detecting engine defects.

- **Automatic Pruning**: Succeeded operations older than 7 days are pruned after successful sync passes to maintain lightweight SQLite performance.

### 32.3 Pure Domain Conflict Resolution (`SyncConflictPolicy`)
- **Non-Destructive Solo Merge**: Completed status is strictly monotonic; valid completions are never revoked by empty or incomplete remote records.
- **Personal Best Preservation**: Solve times preserve the best valid positive time (`min(local, remote)` for times > 0); zero or negative times never overwrite valid records. Fewest moves and fewest hints are preserved.
- **First Completion History**: Earliest historical completion timestamps are preserved across synchronizations.
- **Daily Challenge Reconciliation**: Offline local participation is preserved for calendar history and streaks; leaderboard eligibility remains strictly server-authoritative.

### 32.4 Spring Boot Backend Synchronization Monolith Module
- **Endpoints**: `POST /api/v1/sync/batch` and `GET /api/v1/sync/progress` under `SyncController`.
- **Distributed Idempotency**: `SyncService` tracks processed `operationId`s in-memory, returning `IGNORED_DUPLICATE` without duplicating counts, streaks, or statistics.
- **Partial Batch Failure Handling**: Individual operations in a batch return distinct status codes (`SUCCESS`, `IGNORED_DUPLICATE`, `CONFLICT`, `REJECTED`), allowing client to retry only failed operations.

### 32.5 Background Synchronization via WorkManager
- **`SyncWorker` & `SyncScheduler`**: CoroutineWorker utilizing Hilt's `EntryPointAccessors` with `NetworkType.CONNECTED` and battery constraints. Periodic sync enqueued every 6 hours; expedited one-time requests triggered on reconnect.
- **Boot Restoration**: `BootCompletedReceiver` restores periodic WorkManager sync scheduling upon system restart.

### 32.6 Guest Linking & Account Lifecycle Safety
- **Guest-to-Account Migration**: `rebindOperationsToNewOwner` atomically migrates pending guest operations upon linking, ensuring zero guest progress loss.
- **Account Deletion Safeguard**: Deleting an account purges all queued operations for that player ID, preventing stale sync queues from recreating deleted accounts.
