## 3. Non-Color Dependence (WCAG 1.4.1)

Zynpath enforces strict multi-modal indicators so colorblind players (protanopia, deuteranopia, tritanopia, and achromatopsia) have equal gameplay clarity:

1. **Checkpoints:**
   - Identified by prominent bold numerical digits ($1, 2, 3 \dots N$).
   - Sequence order is indicated by the number value itself, never by color gradient.
   - Visited state changes the stroke outline to a solid fill and displays a checkmark or highlighted numeric badge.
2. **Walls (Blocked Edges):**
   - Rendered as thick solid bars placed precisely on cell borders, accompanied by tactile corner caps.
   - Walls are distinct from visited path segments (path segments have rounded caps that connect cell centers).
3. **Current Path Head:**
   - Distinguished by an animated pulsing ring and directional arrow glyph pointing toward the current drag direction.
4. **Interactive vs Locked Levels:**
   - Locked levels display an explicit padlock icon (`Icons.Default.Lock`) and disabled opacity.
   - Earned stars are represented by filled star glyphs vs empty star outlines.

## 4. Screen Reader Semantics & TalkBack Navigation (WCAG 1.3.1, 4.1.2)

### 4.1 Semantic Labeling Strategy
Each cell on the puzzle board contains an accessible descriptor generated by `buildCellAccessibilityDescription()`:
- **Example Start Cell:** *"Row 1, Column 1. Checkpoint 1. Starting position. Visited as step 1 of 25. Wall to the East."*
- **Example Intermediate Cell:** *"Row 2, Column 3. Empty cell. Visited as step 8. Path connects from West to South."*
- **Example Checkpoint Cell:** *"Row 4, Column 2. Checkpoint 3. Unvisited. Required next checkpoint is Checkpoint 2."*
- **Example Completed Victory:** *"Puzzle completed successfully! All 25 cells visited in correct checkpoint order. Elapsed time: 42 seconds. Score: 3 stars."*

### 4.2 TalkBack Gameplay Action Model
While touch-drag path drawing is the primary interaction for sighted users, Zynpath provides an alternative accessible discrete interaction mode:
- **Cell Tap to Extend:** Tapping an adjacent valid orthogonal cell appends it to the active path.
- **Custom Accessibility Actions:**
  - *"Undo last move"* (Triggered via two-finger double-tap or TalkBack local context menu).
  - *"Reset path to start"*.
  - *"Request hint"*.

## 6. Motion, Audio, and Haptic Accommodations (WCAG 2.2.2 & 2.3.1)

1. **Reduced Motion:**
   - The app monitors `Settings.Global.TRANSITION_ANIMATION_SCALE` and Compose `LocalReducedMotion`.
   - When reduced motion is active, path line drawing renders instantly without spring transitions, celebration confetti is replaced with a static victory card, and pulsing glow effects are disabled.
2. **Haptic Feedback:**
   - Distinct vibration patterns for cell entry, checkpoint reached, invalid wall collision, and victory.
   - Fully toggleable in Settings; defaults to Off if device lacks an amplitude-controlled vibrator.
3. **Sound Effects:**
   - Independent volume sliders for SFX and Ambient audio.
   - Complete mute toggle available with single tap.
   - Gameplay information is never conveyed exclusively through audio cues.

## 7. Known Environment Limitations

- **Physical TalkBack Gesture Verification:** Automated Robolectric semantics trees verify all content descriptions, state descriptions, and custom actions. Physical finger-swiping and TalkBack audio feedback are **BLOCKED** on this host due to the absence of a running hardware Android device with Google Play Services / TalkBack daemon.
