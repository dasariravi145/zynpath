# Zynpath Data Flow & Storage Inventory

**Status:** Authoritative  
**Domain:** End-to-End Data Flow, Retention, and Storage Mapping  

---

## 1. Data Flow Architecture Overview

Zynpath organizes all data into two distinct operational domains:
1. **Device-Sandboxed Domain:** Local SQLite (`Room`), Android `DataStore` preferences, and `AndroidKeyStore` hardware-encrypted session files.
2. **Authoritative Cloud Domain:** Spring Boot REST endpoints, WebSocket session registries, relational database persistence, and external service gateways (Google Play Billing, Google Mobile Ads).

```
[Android Device]
  ├─ User Touch / Canvas Movement ──> In-Memory State (Ephemeral)
  ├─ Local Level Stars / Progress  ──> Room: level_progress (Local)
  ├─ Player Settings (SFX/Haptics) ──> DataStore: user_preferences (Local)
  ├─ Hardware Session Secrets      ──> KeyStore: zyn_secure_session.enc (Local, Non-Exportable)
  │
  │ (Encrypted HTTPS / WSS via TLS 1.3)
  ▼
[Spring Boot Cloud Backend]
  ├─ /api/v1/auth/session          ──> SessionSecurityService (Token verification)
  ├─ /api/v1/account/*             ──> AccountManagementService (Profiles, Settings, Deletion)
  ├─ /api/v1/puzzle/validate       ──> AuthoritativePuzzleValidator (Move legality)
  ├─ /api/v1/billing/*             ──> SubscriptionService (Google Play purchase token hashes)
  └─ /api/v1/ads/verify            ──> AdMob SSV Webhook (Bonus hint credits)
```

## 2. End-to-End Data Category Mapping

### Category 1: Guest Identity & Local Progression
- **Source:** Generated locally upon initial app launch on the Android device.
- **Data Elements:** Guest UUID (e.g. `guest_3f9a...`), unlocked world indices (1–6), level completion stars (1–3), completion time in milliseconds, moves count.
- **Local Storage:** Room database `zynpath_database` (table `level_progress`), DataStore `user_preferences`.
- **Backend Storage:** None (Stored 100% locally on device in Guest mode).
- **Third-Party Recipient:** None.
- **Retention Period:** Retained indefinitely on device until app uninstallation or until user triggers **"Reset Local Guest Progress"**.
- **Deletion Behavior:** Cleared immediately upon tapping **Settings** → **"Reset Local Guest Progress"**.
- **Security Measures:** Stored within the private Android app sandbox (`/data/data/com.zynpath.game/databases/`).

### Category 2: Authenticated Cloud Identity & Profile
- **Source:** Created when the player voluntarily links a Google or Facebook account.
- **Data Elements:** Cloud Player ID, Public Zynpath ID (`ZYN-XXXXX`), display name, avatar frame ID, created timestamp.
- **Local Storage:** `zyn_secure_session.enc` in app files directory.
- **Backend Storage:** Relational database `player_accounts` table.
- **Third-Party Recipient:** Google Identity Services / Facebook Login (token verification only).
- **Retention Period:** Retained for the lifetime of the active account.
- **Deletion Behavior:** Irreversibly purged across all backend tables upon self-service account deletion.
- **Security Measures:** In-transit TLS 1.3; device-side AES-GCM encryption with Android KeyStore; server-side deny-by-default `@RequireAccess(AUTHENTICATED)` role verification.

### Category 3: Online Multiplayer & Competitive Match History
- **Source:** Generated during live Quick Duel, Friend Duel, or Mini League matches.
- **Data Elements:** Match ID, participant IDs, puzzle fingerprint, start timestamp, completion time, final placement (1st–5th), rating delta.
- **Local Storage:** Ephemeral in-memory Compose state.
- **Backend Storage:** Relational database `match_history` and `competitive_stats` tables.
- **Third-Party Recipient:** None.
- **Retention Period:** Retained to power competitive ladders and player history stats.
- **Deletion Behavior:** When an account is deleted, completed matches are preserved with the deleted player's entry sanitized to `[Deleted Player]` to prevent distorting opponent records and leaderboard mathematics.
- **Security Measures:** Server-authoritative `ServerPuzzleValidator` dual-win verification; anti-spoofing player ID derivation strictly from `SecurityContext`.

### Category 4: Daily Challenge Records
- **Source:** Generated when player solves the canonical UTC daily puzzle.
- **Data Elements:** UTC date (YYYY-MM-DD), completion status, moves count, elapsed seconds, streak count.
- **Local Storage:** Room database `daily_challenge_progress` table.
- **Backend Storage:** `daily_challenge_attempts` table.
- **Third-Party Recipient:** None.
- **Retention Period:** Retained locally and on server for leaderboard historical ranking.
- **Deletion Behavior:** Purged on account deletion.
- **Security Measures:** SHA-256 deterministic puzzle seeding; dual-win path validation.

### Category 5: In-App Purchases & Subscriptions
- **Source:** Generated by Google Play Billing library during purchase flow.
- **Data Elements:** Google Play Order ID, Purchase Token, SKU / Product ID (`zynpath_premium_monthly`, `zynpath_premium_6months`), Entitlement State, Purchase Timestamp, Expiration Timestamp.
- **Local Storage:** DataStore cached entitlement state (bounded 30-day offline cache).
- **Backend Storage:** `subscription_entitlements` table (stores SHA-256 hash of purchase token; raw billing tokens are never logged or exposed).
- **Third-Party Recipient:** Google Play Developer API (server-to-server verification).
- **Retention Period:** Retained during active subscription plus statutory financial retention period (7 years) for tax, accounting, and anti-fraud defense.
- **Deletion Behavior:** Account deletion unlinks the entitlement from the player profile; anonymized transaction hashes are retained in audit tables.
- **Security Measures:** SHA-256 token hashing; ownership conflict locking; server-authoritative feature gating.

### Category 6: Optional Rewarded Advertising
- **Source:** Google Mobile Ads (AdMob) SDK upon voluntary player engagement.
- **Data Elements:** Ad Unit ID, Reward Item (`HINT_CREDIT`), AdMob Server-Side Verification (SSV) transaction ID.
- **Local Storage:** DataStore `rewarded_hint_credits` (wallet cap of 10 bonus credits).
- **Backend Storage:** `rewarded_ad_transactions` table.
- **Third-Party Recipient:** Google LLC (AdMob).
- **Retention Period:** Daily transaction log resets at UTC midnight (daily cap of 5 ads).
- **Deletion Behavior:** Local credits erased on guest reset; backend transaction records purged on account deletion.
- **Security Measures:** Server-Side Verification (SSV) cryptographic ECDSA signature validation; duplicate transaction rejection.

### Category 7: Diagnostics & Technical Telemetry
- **Source:** Internal `ErrorClassifier` and network interceptors.
- **Data Elements:** HTTP response codes, error category (e.g. `NETWORK_UNREACHABLE`, `INVALID_MOVE`), app version string, device model.
- **Local Storage:** Ephemeral in-memory ring buffer (last 50 events).
- **Backend Storage:** Rolling operational log files (retained 30 days).
- **Third-Party Recipient:** None.
- **Retention Period:** 30 days maximum.
- **Deletion Behavior:** Auto-rotated and overwritten.
- **Security Measures:** Structured redaction of all headers, bearer tokens, and player identifiers.
